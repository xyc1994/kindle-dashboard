# 显示与交互设计

## 设计原则

- 一眼看到“现在是否需要我介入”，而不是堆满数据。
- 页面只在信息变化时刷新；低价值秒级状态不进入墨水屏。
- 高对比、少阴影、少灰阶、大字号，适配 PW3 竖屏 `1072 × 1448`。
- Kindle 不持有外部服务凭据，不执行任意命令。

## 页面一：首页

从上到下：

1. 时间、日期、上海市黄浦区天气、当天最高/最低温。
2. 动态介入卡：只显示当前优先级最高的一项。
3. Codex 当前任务：标题、状态、持续时间、最近有效进展。
4. Codex 额度：5 小时与周额度的剩余百分比、重置时间。
5. Obsidian 接下来三项：P0、逾期、今日到期优先。
6. 更新时间、电脑在线状态、Kindle 电量。

天气图形从项目已有的 `QWeather-Icons-1.8.0` 按和风天气 condition code 选择 SVG；生成 Kindle 图片前统一转为高对比黑白或有限灰阶，不在 Kindle 端解析字体图标。

### 介入卡排序

1. Codex `waitingOnApproval`。
2. Codex `waitingOnUserInput`。
3. Codex `systemError` 或任务失败。
4. Obsidian 逾期 P0/P1。
5. Obsidian 今日到期 P0/P1。
6. 天气预警或数据源长时间失效。

没有介入项时，介入卡缩成一行“当前无须处理”，将空间让给任务和待办。

## 页面二：Codex

- 当前活动任务及最近一次有意义的状态更新。
- 最多三项等待介入操作。
- 最近任务状态：执行中、等待、异常、完成、未加载。
- 5 小时和周额度剩余比例及重置时间。
- 第一阶段只提供“在电脑处理”，不在 Kindle 上直接批准或拒绝。

## 页面三：Obsidian 待办

- “必须处理”：逾期与 P0。
- “今天”：今天到期的 P1/P2。
- “接下来”：未来七天内最重要的任务。
- 正式来源：`05_Memos/Memos_Active/**/*.md` 中 `status: todo` 或 `in_progress` 的结构化卡片。
- 补充来源：`01_Daily/**/*.md` 中明确带 `#kindle` 的未完成复选框。
- 不自动显示普通日记复选框，避免把长期观察和研究问题误判为行动任务。

## 底部触摸区

```text
┌────────────┬──────────────┬────────────┐
│   上一页    │  刷新 / 处理  │   下一页    │
└────────────┴──────────────┴────────────┘
```

第一阶段：

- 上一页、下一页；
- 手动刷新；
- 临时隐藏提醒；
- 通知 Windows 打开相应 Codex 任务。

第二阶段在完成冲突保护后再启用：

- 标记 Obsidian 待办完成；
- 修改轻量任务状态；
- 低风险 Codex 操作，但仍需二次确认页。

## 屏幕刷新规则

- Windows 每 5 秒生成轻量状态摘要，但内容 hash 不变时不生成新画面。
- 任务、介入项、天气或待办变化时立即生成新 PNG。
- 时钟每分钟允许一次局部刷新。
- Kindle 每 5 秒检查控制序号，只在序号变化时下载图片。
- 普通变化使用 GL16 局部/轻刷新；累计 5 次轻刷新或每 10 分钟执行一次 GC16 全刷。
- 电脑离线时保留最后一帧，Kindle 在本地叠加“电脑离线”提示。
